# 전체 객관식 해설 적용과 저장·채점 복구 검증 — 12.16.29

## 요청 완료 범위
이전 12.16.28에서 수정한 저장 안정성과 완료된 채점 결과 보존 기능은 유지하고 재검증한다. 일부 어휘에만 제공되던 선택 오답별 설명의 적용 범위를 현재 사용하는 등록 객관식 전체로 확대한다. 기존 답안, 점수, 진도, 어휘 단계, 주관식·객관식 비율, 최소 학습시간, 문장 사용 완료 조건, 날짜 전환/보관 기능은 변경하지 않는다.

## 해설 적용 수량
사전 제작 정적 문제은행을 실제 선택 함수와 동일한 어휘 필터로 세었다.

| 구분 | 객관식 문항 | 오답 보기별 해설 |
|---|---:|---:|
| 현재 출제 대상 사전 제작 문항 | 13,590 | 54,360 |
| 이전 판본 등 과거 기록 복구용 문항 | 3,378 | 13,512 |
| 등록된 사전 제작 판본 전체 | 16,968 | 67,872 |

첫 행에는 12.16.27의 사전 추가 객관식 18개가 포함된다. 이전 판본은 과거에 저장된 동일 문항의 해설 복구에만 사용하며 은퇴/제외 어휘를 새로 출제하지 않는다. 숫자는 문항과 보기별 적용 범위이지, 서로 다른 학습 어휘 수나 독립 전문가가 작성한 해설 수가 아니다.

별도 Supabase 현재 정책 문제은행의 객관식 44개에도 등록 원문을 조회해 설명을 복구하는 읽기 전용 경로를 추가했다. 정적 은행 수량과 무조건 합쳐 서로 다른 신규 문항 수로 표시하지 않는다. 현재 정책을 벗어난 구버전 DB 문항을 승인하거나 재활성화하지 않는다.

## 설명의 방식과 한계
기존 11개 핵심 어휘·66문항·오답 264개에 직접 작성한 편집 해설은 유지한다. 나머지 설명은 등록된 문항의 선택 보기, 어휘 뜻, 대조되는 뜻/상황, 정답 보기와 지문 문장을 연결하는 규칙 기반 비교 해설이다. 지문에서 뒤 문장이 핵심 단서인 경우를 놓치지 않도록 앞뒤 문장을 함께 인용한다. 확인되지 않은 인물 의도나 새로운 지문을 만들어 넣지 않는다.

즉, 선택한 보기마다 설명이 연결되는 기능과 적용 범위는 전체로 확장했지만, 67,872개를 각각 사람이 별도 집필·독립 의미 검수했다고 주장하지 않는다. 출처 설명은 `registered-source-contrast`이고 독립 사람 검수 완료 표시는 사용하지 않는다. 검증은 문항별 네 오답의 설명 존재·서로 다른 보기 연결·원문 인용·보기 순서 변경·정답 불변 및 표본 읽기 중심이다. 원문 자체의 교육적 적절성까지 전부 새로 보증하는 작업은 아니다.

유료 OpenAI 문항 생성이나 해설 생성은 호출하지 않는다. 현재 등록된 자료로 설명을 구성해 문제와 함께 전달한다. 이미 저장된 문항은 인증된 읽기 전용 API에서 소유 계정·문항·지문·뜻·보기 텍스트·정답 표시를 대조한 뒤 해설만 보충한다. 다른 계정이나 변조된 지문은 받지 않는다. 앞으로 추가되는 등록 문항에도 같은 설명 전달 기능이 적용된다.

## 저장·채점 복구 재검증
기존 12.16.28의 IndexedDB 이관, 기기/서버 저장 실패 분리, 완료된 채점 결과의 저장 재시도·서명 결과 복구·중복 유료 시작 차단 로직을 변경하지 않았다.

실제 GitHub CI의 Chromium 브라우저에서 시험용 계정 키와 합성 데이터만 사용했다. 사용자 계정 로그인이나 실제 학생 답안은 사용하지 않았다. 뷰포트는 1024×768, 터치 설정이며 실제 Android 태블릿 하드웨어 시험은 아니다.

통과한 브라우저 시험:
- 실제 localStorage를 채워 QuotaExceededError가 발생하는 상태를 만듦.
- 실제 IndexedDB에 600만 글자 데이터와 대기 답안 2개 저장을 확인함.
- 페이지 새로고침 후 600만 글자와 대기 답안 2개를 그대로 복구함. 다른 계정 키는 비어 있음.
- 기기 저장 실패를 주입해도 배포용 실제 cloudSave 함수가 별도의 서버 저장 요청을 실행함. 서버 응답은 시험용 모의 응답임.
- 기기·서버 양쪽 실패 시 재시도 상태와 '저장 실패 · 창을 닫지 말고 재시도' 경고를 유지함.
- 저장 환경이 회복되면 다시 저장하는 데 성공함.
- 이미 받은 채점 결과는 실제 requestGrade 함수에서 추가 네트워크 요청 없이 재사용함.

브라우저 통과 이력: run 38683641842, head 4943537088ca488fb0700f67d9f971fe43a920b6. 최종 브랜치에서도 같은 시험을 다시 실행한다. 결과는 CI artifact `browser-recovery-evidence`의 JSON과 화면 캡처로 남긴다.

서버 채점 복구는 기존 grade-preservation/grade-cache 시험에서 결과 저장의 일시·지속 실패, 재요청, 새 프로세스, 서명 변조 및 다른 계정 거부를 재검증한다. 실제 유료 모델 호출은 사용하지 않는다. 결과와 복구 자료를 전부 잃은 상황은 임의로 정답을 만들거나 재과금하지 않고 복구 확인 상태를 유지한다. 양쪽 저장소가 모두 불능인 동안 전원이 끊기는 상황까지 무손실을 보장하지 않는다.

## 검증과 운영 변경
`node scripts/verify-all.mjs`의 45개 검증과 실제 public 빌드를 실행한다. 전체 객관식 문항·정답·보기·허용 답안을 변경하지 않는지, 모든 변형을 실제 공급 함수로 얻을 수 있는지, 보기 순서가 바뀌어도 같은 문구에 설명이 붙는지 검사한다. 보고서는 `test-results/bank-wide-feedback.json`이다.

Supabase migration `registered_choice_feedback_readonly_recovery`를 적용했다. 등록된 현재 정책 객관식 44개 원문은 모두 조회되었고 지문 변조 및 다른 소유자는 거부되는 것을 읽기 전용 트랜잭션에서 확인했다. 비로그인 사용자의 실행 권한은 없다. 학생 학습 상태를 갱신하는 SQL은 실행하지 않았다.

실제 사용자의 태블릿에서 화면 조작을 직접 검증한 것은 아니다. 앱에 저장 완료가 표시된 다음 새로고침하면 새 해설 연결이 적용되며, 앱 데이터나 학습 기록을 삭제할 필요는 없다.
