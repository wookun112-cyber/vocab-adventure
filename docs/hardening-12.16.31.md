# 12.16.31 — 이어서 반영한 전체 점검 개선

2026-10-15의 12.16.29 점검과 DB 저장 시간 초과 긴급 수정을 기준으로 한다. `atomic-tree-learning-save.sql`과 기존 기록 보존·날짜 전환·채점 결과 복구는 유지한다. 운영 학습 상태를 수정하는 migration은 없다.

다른 작업에서 먼저 반영된 `1ff7fb5`의 하루 25~30분 누적 제한·자동 저장 종료도 병합해 유지한다.

## 동작 수정

- A1: 서비스 워커 교체는 새 버전 알림만 표시한다. 사용자가 업데이트를 선택하면 음성/시간 측정을 멈추고 현재 미제출 답안까지 체크포인트한다. 기기 쓰기 완료 또는 서버 저장 성공을 확인하고, 저장 중 기록/계정이 바뀌지 않았을 때만 새로고침한다. 채점 요청·학습 전환 중에는 보류한다. 이미 실행 중인 구버전의 최초 전환까지 소급 보호하지는 못한다.
- A2: 새 유료 채점은 기존 문제은행 소유 가족 계정에만 허용한다. 서버에 저장된 현재 학습의 배정 문항과 과제 유형·뜻·지문·허용 답안이 일치하고 등록 원문 검증을 통과해야 한다. 저장이 늦으면 409 대기로 남기고 생성하지 않는다. 캐시/서명 결과 복구는 새 과제 인가와 예산을 소비하지 않는다.
- 유료 요청 보호: 가족 계정 전체 하루 600회, 분당 20회, 동시 진행 3회. 한국시간 자정을 사용하고 새 모델 요청 시작만 원자적으로 집계한다. 객관식/고정 답/캐시 조회에는 제한을 적용하지 않는다. 관리자가 비공개 `grade_access.daily_limit`에서 변경할 수 있다. 금액 한도가 아닌 호출 수 보호이며 모델 단가와 별개다. 일일 한도에 걸린 답안은 저장하고 다음 날 재시도한다.
- A3: 음성 인식은 계정·프로필·세션·문제 위치·문항 객체에 묶는다. 화면/문제/프로필/계정 전환, 직접 타이핑, 제출, 숨김 때 중단한다. 늦은 결과와 이전 인식기의 종료 이벤트는 새 답안을 바꾸지 못한다. 음성 초안도 즉시 저장한다.
- A4: 해설 조회 실패/빈 결과는 요청 캐시에서 제거한다. 현재 해설의 다시 불러오기 버튼으로 재시도한다. 성공한 설명만 재사용하며 점수 변경이나 유료 생성은 하지 않는다.

## 안내·성능·관측

- 하루 학습량과 난이도 안내를 하나의 정책 문구에서 설정·순위·부모 리포트로 공급한다.
- 설정에 마지막 서버 저장 확인 시각, 아이별 채점 대기/기존 결과 복구/비용 보호 대기를 표시한다. 기존 동기화와 이어하기를 안내하고 강제 재과금 버튼을 만들지 않는다.
- 일별 활동에 독립 확인과 도움·반복 연습을 구분한다. 과거 미분류 자료는 추정하지 않으며 정답률 분모·점수·시간을 변경하지 않는다.
- 긴 객관식 해설은 뜻 차이를 먼저 보여 주고 지문 근거는 펼쳐 본다. 보기와 정답 자체를 일괄 변경하거나 쉬운 도입 문항을 삭제하지 않는다.
- 모든 과거 판본의 해설을 시작 때 만들지 않고 필요한 어휘만 초기화한다. 같은 환경의 새 프로세스 측정에서 문제은행 import 933ms/108MiB → 193ms/44MiB. 실서비스 전체 응답속도나 태블릿 측정값은 아니다.
- 추가 어휘 조회는 가족 전체 상태 대신 선택한 아이의 난이도·어휘 이력·현재 목표만 읽는다. 점검 당시 2,590,398바이트에서 프로필별 113,317~369,075바이트로 줄었다. 실제 REST 투영 요청의 HTTP 200/비로그인 0행도 확인했다.
- 채점 로그에는 상태·오류 코드·캐시 여부·걸린 시간만 남기고 답안·인증정보를 남기지 않는다. main push도 기존 CI를 실행하며 Vercel 빌드는 전체 검증 실패 시 중단한다.

## 검증 및 반영 순서

1. `node scripts/verify-interaction-hardening.mjs`: 저장 지연/실패/동시 변경, 실제 배포 코드의 미제출 초안 복구, 늦은 음성 결과, 해설 실패 후 재시도.
2. `node scripts/verify-grade-access.mjs`: 다른 인증 계정·미배정·과제 종류·예산 차단과 캐시 복구. 모델 호출은 모의 함수다.
3. `database/grading-access-budget.sql` 적용 전 롤백 시험에서 운영에 저장된 주관식 68개 모두 인가, 문구 변조 68개 모두 거부.
4. `database/verify-grade-access.sql`: 롤백으로 일일/분당 한도, 중복 시작, 한도 이후 캐시 조회, 다른 계정/비로그인 역할 확인. 시험 자료를 남기지 않는다.
5. 전체 회귀·public 빌드·CI 브라우저 복구 검증 후 DB와 앱을 배포한다. 실제 아이 답안을 제출하거나 유료 API로 시험하지 않는다.

## 범위의 한계

문항 28,150개 전체의 독립적인 의미 검수나 실증적 난이도 표준화를 완료했다고 주장하지 않는다. 유사어를 경쟁 보기로 바꾸는 문항별 재작성은 정답 유일성 검토와 별도 판본 등록이 필요한 후속 편집 작업이다. 현재 원문의 등록·변조 검증과 모든 오답별 설명 연결은 유지한다. 장기 데이터의 문항 ID 분리와 단계별 파일 분할은 이번의 위험이 작은 최적화와 별도이다. GitHub 강제 브랜치 보호 설정과 외부 장애 알림은 현재 연결로 적용하지 않았다. 실제 Android 마이크/두 물리 기기를 사용한 확인도 별도로 필요하다.
