# 유료 자동 생성 없는 문제은행 운영 — 12.16.27

## 적용 범위
어휘탐험의 기본 문제 준비 작업과 어휘 확장 API를 사전 등록 문제은행·고정 안내문 기반으로 전환한다. 학습 중 질문 공급뿐 아니라 배경 준비 작업에서도 기본 경로는 OpenAI 문제 생성·생성 문항 AI 검수를 호출하지 않는다. 자유문장 및 미등록 대체답의 의미 채점은 기존 API와 중복 채점 캐시를 유지한다. ChatGPT에서 작업한 비용과 앱 API 사용료는 같은 항목이 아니다.

## 구버전 678문항
운영 DB의 이전 정책 문항 678개에 대해 현재 어휘 등록 상태, 제외 대상, 단계·뜻, 문제 유형, 설명 유무, 객관식 5개 보기·유일 정답 등 구조 검사를 했다. 기존 문항의 정책 값을 일괄 최신으로 바꾸거나 학습 기록을 수정하지 않았다.

- 622개: 제외/은퇴 어휘, 과거 문제 유형, 단계 변경, 고정 문장쓰기 안내로 대체할 대상 등의 사유로 재활성화하지 않음.
- 56개: 구조상 문제 없는 후보이나 같은 어휘·유형의 최신 등록 문항이 있으므로 그 문항을 우선 이용. 구버전 자체를 새로 의미 검수했다고 표기하지 않음.

이는 전수 **구조 점검 및 재사용 경로 분류**이며 678개의 독립적인 의미 검수나 사람의 검수를 완료했다는 뜻이 아니다. 여러 제외 사유는 한 문항에 중복될 수 있다.

## 부족 문항과 반복 요청
출제 전에 준비된 문제·기본 은행·추가 사전 제작 문항·기존 고정 안내를 확인한다. 아직 시작하지 않은 일반 새 단어만 같은 어휘 단계, 같은 문제 유형, 같은 학습 카드 요구를 만족하는 다른 미학습 단어로 선택할 수 있다. 복습 예정 어휘, 낮은 단계 보충, 이미 준비된 문항 및 중단한 학습의 원래 목표는 바꾸지 않는다.

그래도 필요한 문항이 없으면 `bank_supply_required`로 남겨 자동 반복 실행을 중단한다. 준비된 다른 문제·답안은 보관한다. 동일 어휘·뜻·단계·유형·도움 수준의 요청은 SHA-256 식별자로 합쳐 비공개 보충 목록에 기록한다. 앱 화면은 이 상태를 API 잔액 부족이나 계속 생성 중으로 표시하지 않는다.

후속 사전 제작 문항이 등록되면 같은 계정의 해당 어휘·유형을 기다리던 미사용 작업만 다시 준비 후보로 올린다. 재개해도 기존 검증을 생략하지 않으며 새 유료 생성은 허용되지 않는다. 부족한 내용을 ChatGPT가 사용자의 별도 작업 없이 자동으로 작성하는 기능은 아니다.

## 이번 사전 보충
`객관적` 5단계, `예측하다` 3단계, `추측` 3단계에 각 10슬롯을 등록했다. 합계는 **새 지문·보기 27개와 문장쓰기 고정 안내 3개, 총 30슬롯**이다. 예측의 실제 등록 표제어는 `예측하다`이고 문장 빈칸에서는 `예측`을 사용한다.

각 어휘는 객관식 문맥 3, 쓰임 판단 3, 문맥 회상 3, 예문 없는 자기 문장 쓰기 1로 구성하며 해설을 함께 저장한다. 기존 문제를 먼저 사용하고 같은 유형의 새 지문이 소진되면 추가 변형을 이용한다. 기존 문제를 덮어쓰지 않았다. 새 콘텐츠는 ChatGPT에서 사전 작성했으며 `aiVerified:false`, `independentHumanReview:false`를 유지한다.

DB에서 등록 30개 전부가 기존 원문 대조 검증을 통과했고, 지문 변조 및 다른 소유자 입력은 0개 통과했다. 코드에서도 30슬롯 구조·활용형·동의어 인정·중복 지문 배제를 검사했다. 앱의 유료 생성 API를 이용해 이번 문항을 작성하거나 검수하지 않았다.

## 재현 및 후속 보충
- `node scripts/verify-all.mjs`: 기존 저장·다음 날 새 학습·채점·문제은행 및 비용 차단 회귀 검사.
- `node scripts/export-offline-bank.mjs /명시적인/로컬경로/content.json`: 검증된 편집 원본을 JSON으로 내보냄. API 호출이나 DB 변경은 하지 않으며 기존 파일은 덮어쓰지 않음.
- 편집 원본은 `lib/server/offline-bank-supplement.js`, 실제 공급은 `lib/server/offline-bank-runtime.js`. 은행 원문은 공개 정적 프런트엔드 배포 목록에 넣지 않음.
- 추가 팩은 새 revision으로 작성하고 구조·의미 점검 후 `bank_authoring_items`에 한 번에 등록하며, 같은 revision을 검증 없이 덮어쓰지 않음. 런타임 및 DB의 정확한 revision 검증도 함께 반영.

운영 DB 적용 이력: `bank_only_supply_queue_and_legacy_audit`, `register_offline_supplement_canonical_headwords`, `record_preflight_deficits_and_requeue_on_offline_content_arrival`. 변경 SQL은 Supabase migration history에 보관되어 있다. 새 테이블은 모두 RLS를 켜고 anon/authenticated 직접 접근을 차단했다.

## 보존 및 한계
답안·점수·학습시간·부모 리포트·현재 수준·채점 기준·날짜 전환 기능을 초기화하지 않는다. 실제 준비 함수의 11개 수준 테스트는 원격/유료 생성 호출 0회로 기본 세트를 완성했다. 없는 과거 유형은 임의의 다른 문제나 정답으로 바꾸지 않고 원형을 보관한다. 모든 미래의 콘텐츠 부족이 사라졌다는 보장은 아니며 필요한 내용은 사전 보충해야 한다.

배포 후 실제 비용 절감률은 사용량으로 따로 측정해야 한다. 전체 API 비용 0원이나 특정 절감률을 보장하지 않는다. 실제 태블릿에서의 마지막 조작 확인은 별도이다.
