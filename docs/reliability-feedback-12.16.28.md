# 저장·채점 결과 보존·선택 오답 해설 — 12.16.28

## 사용자 요청과 범위
저장 안정성, 이미 완료된 유료 채점 결과의 보존, 선택한 오답에 맞는 해설만 변경한다. 객관식·주관식 비율, 최소 25분, 단어 사용 확인, 오답 반복/추가 학습, 다음 날 새 학습 정책은 바꾸지 않는다.

## 기기 저장
큰 가족 상태와 아이별 복구 기록을 IndexedDB에 저장한다. 기존 localStorage 기록은 읽어 들인 뒤 IndexedDB 트랜잭션 완료를 확인한 경우에만 동일한 옛 복사본을 제거한다. 다른 값이나 계정의 데이터를 일괄 삭제하지 않는다. IndexedDB가 사용할 수 없으면 기존 저장소로 안전하게 대체한다.

기기 저장에 실패하더라도 서버 저장은 별도로 시도한다. 두 저장이 모두 실패하면 재시도 상태와 현재 메모리의 답안을 유지하고 '창을 닫지 말고 재시도' 안내를 표시한다. 실패한 로컬 쓰기를 '기기에 보관됨'이라고 표시하지 않는다. 다만 모든 저장소가 동시에 실패한 상태에서 기기 전원이 끊기는 상황까지 무손실을 보장할 수는 없다.

## 채점 결과
AI 채점 시작을 DB에 먼저 표시한다. 채점에 성공하면 결과 저장만 최대 세 번, 정해진 시간 안에서 재시도하며, 실패했더라도 이미 받은 점수와 피드백을 반환한다. 서버의 짧은 수명 캐시와 위변조 검증용 서명 결과를 함께 사용한다. 클라이언트도 받은 결과를 대기 작업에 저장하고, DB 미보관 결과의 서명 자료를 기기에 보관해 재접속 시 결과 저장부터 복구한다.

이미 시작한 채점의 DB 작업 잠금이 만료됐다는 이유만으로 새 유료 채점을 허가하지 않는다. 결과와 서명 자료를 모두 잃은 드문 장애는 '채점 결과 복구 확인 필요'로 중단하고 임의 정답 처리나 반복 유료 호출을 하지 않는다. API 잔액 부족처럼 확정적으로 거절된 요청은 기존 재시도 정책을 유지한다. 서명은 계정·과제·답안을 묶어 검증하며 다른 답안이나 계정에 사용할 수 없다.

## 선택한 오답별 해설
근거, 기준, 의견, 객관적, 예측하다, 추측, 가늠하다, 가루, 도시화, 재진술, 함축: 11개 핵심 어휘의 기존 객관식 66문항에 오답 보기 264개분의 이유를 사전 작성했다. 이는 전체 문제은행의 모든 오답 해설을 새로 완성했다는 뜻이 아니다.

보기 순서를 섞어도 설명이 같은 보기 문장에 붙는다. 기존 정답 표시·문제 문장·학습 난이도는 그대로다. 앞으로 제작되는 이유 필드도 학생 화면까지 전달하도록 수정했다. 이미 저장된 구버전 문제는 인증된 읽기 전용 설명 API에서 원래 문제·지문·보기·소유 계정을 대조한 뒤 해설만 보충한다. 유료 문항 생성이나 해설 생성 요청은 사용하지 않는다. 이제 객관식 결과에 실제 선택한 보기 문구도 저장한다.

## 5:5 비율 조사 (2026-10-14 아영 진행 세트)
운영 DB에서 65개 진행 기록을 다음처럼 분리했다.

| 기록 구간 | 객관식 | 주관식 | 합계 |
|---|---:|---:|---:|
| 처음 배정된 기본 15개 | 2 | 13 | 15 |
| 기본 어휘의 후속 학습: 오답 보강·문장 사용 확인 등 | 4 | 22 | 26 |
| 25분 보충 어휘와 해당 어휘의 재학습 | 8 | 16 | 24 |
| 전체 | 14 | 51 | 65 |

65개는 화면 진행 기록이며 순수한 서로 다른 문항 수가 아니다. 채점 대기 등 평가 제외 기록 3개도 포함되어 있다. 제외하면 객관식 14개·주관식 48개다. 이후 문제의 remedial 표시는 오답만을 뜻하지 않는다. 회상 정답을 맞힌 '특징'과 객관식 정답을 맞힌 '고려하다'도 다음에 문장 사용 확인으로 연결됐다. 재학습과 시간 보충은 영향을 주지만, 오답 반복 전의 기본 15개부터 5:5가 아니므로 오답 때문에만 벌어진 차이는 아니다. 이번 변경에서 비율을 조정하거나 비율을 맞추기 위한 새 문제를 더 넣지 않았다.

## 검증 및 한계
실제 배포 변환 코드를 사용하는 저장/날짜 전환 시험, 기기 용량 오류·양쪽 저장 실패·복구, 채점 결과 저장의 일시/지속 실패·프로세스 재시작·서명 변조/다른 계정 거부, 보기 순서 변경과 구버전 설명 보충을 테스트했다. IndexedDB 어댑터는 제어된 트랜잭션 모의 환경에서 완료 전 옛 기록 보존, 600만 글자 데이터, 연속 쓰기 순서, 재시작을 검증했다. 로컬 실제 브라우저 접근은 실행 환경 제한으로 검증하지 못했으며 사용자 태블릿 검증도 별도다.

DB의 시작 표시·만료 후 중복 시작 차단·기존 결과 복구는 트랜잭션 안에서 확인하고 롤백했다. 시험에 실제 AI 유료 요청을 사용하지 않았고 기존 학생 점수나 학습 내용을 수정하지 않았다. 운영 적용 SQL은 database/grade-result-preservation.sql과 Supabase migration history의 preserve_started_grade_and_completed_result에 기록한다.
