# 누적 저장 시간 초과 긴급 수정 — 2026-10-15

## 확인된 장애
사용자 화면에 `저장 지연 · 기록은 기기에 보관됨` 및 `먼저 기존 답안을 서버에 저장해야 해요`가 표시됐다. 문제 생성 비용이나 태블릿 저장 용량 오류로 단정하지 않고 Supabase 로그를 확인했다.

2026-10-15 한국시간 18:05:47, 18:06:31, 18:08:42의 `save_learning_patch` 응답은 HTTP 500, PostgreSQL 코드 57014 (`canceling statement due to statement timeout`)였다. 해당 요청은 약 8초 뒤 취소됐다. DB 로그의 context는 기존 `public.save_learning_patch(jsonb)` 33/65행이며, 특히 `group_values[idx]:=area` 대입 중 누적 변경사항을 합치다 시간 제한에 도달했다. 당시 잠금 대기를 일으키는 다른 장기 쿼리는 관측되지 않았다.

이 문제는 앞서 분리한 기기/서버 저장이나 IndexedDB 이관과 다른 서버 측 병목이다. 기존 소규모 저장 시험과 브라우저의 모의 서버 응답 시험만으로는 실제 서버의 대량 변경 처리 시간을 충분히 검증하지 못했다.

## 적용
`database/atomic-tree-learning-save.sql`의 합치기 함수를 운영 DB에 적용했다. 변경 경로를 트리별로 묶어 각 객체와 배열을 한 번씩 조합한다. 입력 검증은 모아서 수행하고, 말단 변경마다 SQL 경로 배열을 새로 집계하던 처리를 제거했다.

기존 `save_learning_patch(p_operations)` 주소와 요청 형식은 유지한다. 이미 열려 있는 앱도 같은 요청으로 개선된 저장 함수를 사용한다. **시간 제한을 늘리거나, 저장 실패를 성공으로 표시하거나, 전날 학습을 완료 처리한 것이 아니다.** 브라우저·서비스 워커·앱 버전에는 변경이 없어 새로고침이나 앱 데이터 삭제가 필요하지 않다.

소유 계정 RLS, 기존값 대조 충돌 검사, 전체 성공 또는 전체 취소의 원자성, 학습 기록 후퇴 방지, 이전 학습 보관 트리거를 유지했다. 비로그인 역할의 저장 실행 권한은 없다. 겹치거나 모호한 변경 경로는 임의로 적용하지 않는다.

운영 migration 이력:
- prepare_tree_based_atomic_learning_save
- activate_atomic_tree_save_for_existing_clients
- optimize_large_patch_validation_and_leaf_checks

## 검증
- 객체/배열 내부 수정, 배열 뒤 추가, JSON null, 삭제, 동일 요청 재전송, 기존값 충돌 검사 통과.
- 실제 크기의 기존 학습 상태를 기준으로 4,260개 합성 변경을 저장한 초기 시험: 약 1.80초.
- 더 큰 11,360개 시험에서 초기 개선안도 8초 제한에 걸려 입력 검증과 말단 검사를 추가 최적화했다. **최종 구현은 같은 11,360개 변경을 기존 RPC로 약 1.86초에 처리**했다.
- 벤치마크는 인증된 사용자 역할, 8,000ms 제한을 그대로 두고 트랜잭션 안에서 수행했으며 모두 롤백했다. 합성 필드·답안·점수가 운영 기록에 남지 않은 것도 확인했다.
- 저장 충돌 시 앞선 변경도 남지 않는지, 기존 학습 횟수를 줄이는 요청이 차단되는지 확인했다.
- 전날 학습을 보관하고 원래 문제·답안을 그대로 복원하는 전환 함수를 롤백 시험했다. 다른 프로필은 변경되지 않았다.
